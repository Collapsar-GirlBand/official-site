# JIZURA「画面动效模式」用户体验调研与改造建议

调研日期：2026-10-29。对象：当前工作区内 JIZURA 浏览器版。

## 1. 核心判断

当前最需要重做的是编辑流程：用户需要直观看见效果、知道效果发生在哪、只改自己选中的部分，并立即判断修改结果。现在的实现把双画面对比、事件管理、自动生成和全片风格参数放在一起，却缺少直接操作动效的时间轴，导致基本编辑任务绕路。

**建议方向：以时间轴为中心的轻量动效工作区。借鉴 CapCut 的效果片段、Final Cut Pro 的应用前预览、Premiere 的选中对象属性面板、Apple Motion 的行为模型。保留 JIZURA 自动构成的优势，把自动结果变成可理解、可局部修改的对象。**

最先做三件事：

1. 恢复独立动效轨，支持选中、移动、调整持续区间。
2. 取消“点击一个自动事件就固化全片”的隐式修改。
3. 默认用大画面编辑；双画面对比改为用户主动开启。

暂缓增加效果数量、完整曲线编辑器、节点系统。基础编辑闭环完成后，再判断这些投入是否有价值。

## 2. 调研方法与证据边界

- **本项目证据**：检查 `app/body.html`、`app/style.css`、`src/12_ui.js`、`src/08_planner.js`、`src/09_render.js`、`src/05b_registry.js`，并抽查根目录生成版 `index.html`。

- “成熟”指官方资料中已有的交互机制，不表示已证明这些产品的每项设计都优于 JIZURA。网页为动态资料，平台和版本存在差异；不把 CapCut 国际版直接当作国内剪映的实测结果。
- 本轮交付为调研报告，未修改业务实现。

## 3. 当前实现诊断

### 3.1 已有能力值得保留

项目已经具备事件数据结构、强度与时长编辑、撤销入口、自动事件固化、拍点检测、同步对比和效果预览基础设施。不是从零重写引擎。

特别是 `draw()` 使用相同项目、相同时刻和同一渲染器绘制对比，另一侧通过 `noEvents: true` 排除时间点事件；这一对比定义有价值。应保留能力，调整入口、命名和默认状态。

### 3.2 问题与影响

| 级别 | 代码可确认的现状 | 对用户任务的影响／推断 | 建议 |
|---|---|---|---|

## 4. 成熟产品具体怎么做

### 4.1 CapCut：把特效放进时间轴

官方帮助明确描述：网页版把效果拖到视频上方的时间轴，调整持续时间，再移动播放头预览；还特别指出播放头在效果区间外会让用户误以为效果没生效。[来源：CapCut 效果应用帮助](https://www.capcut.com/help/effectss-not-applying-in-capcut)

**值得借鉴**：让效果成为有位置、有长度的时间对象；预览与效果区间保持关联。JIZURA 的短促白闪也应有可选中的时间对象，缩小时可以显示点状标记，放大后显示真实持续区间。

**不直接照搬**：素材商城、热门流量标签和庞大的多轨视频编辑功能。JIZURA 的核心仍是歌词与音乐驱动的文字 PV。

### 4.2 Final Cut Pro：选择之前先看到结果

官方文档提供分类、名称搜索和缩略图扫览；扫览时可在 Viewer 查看效果。确认后拖到目标片段，或双击应用。[来源：Apple 添加视频效果](https://support.apple.com/en-sg/guide/final-cut-pro/ver4e33bc9/mac)

**值得借鉴**：效果库应帮助用户做视觉判断。JIZURA 可以先用固定文字样本展示效果，再允许在当前歌词与背景上临时试听／试看。预览结束恢复，只有“添加”才写入项目。

**适配限制**：浏览器端先让一张悬停或选中的卡片播放，其他卡片显示静帧；不默认让全部效果持续渲染。触屏提供明确的预览按钮。

### 4.3 Premiere：属性围绕选中的对象组织

Effect Controls 显示所选片段的效果，支持展开属性、显示时间轴以及值和速度曲线。官方预设机制还区分按目标时长缩放、锚定入点、锚定出点。[来源：Adobe 效果控件面板](https://helpx.adobe.com/premiere/desktop/add-video-effects/apply-video-effects/about-effect-controls-panel.html)、[Adobe 创建效果预设](https://helpx.adobe.com/premiere/desktop/add-video-effects/apply-video-effects/create-effect-presets.html)

**值得借鉴**：选中什么，就调什么；面板标题显示对象及作用范围。复制效果或应用预设时，要明确跟随歌词起点、歌词结尾，还是保持绝对时间。

**先做简化版**：强度、时长、时间、衰减方式和重置。完整贝塞尔曲线不是第一阶段必要条件。

### 4.4 DaVinci Resolve：把时间上的变化留在时间上下文中

官方 Edit 页说明，曲线编辑器能在时间轴片段下方呈现关键帧位置与动画曲线，并支持不同插值方式。[来源：Blackmagic Design Edit 页](https://www.blackmagicdesign.com/products/davinciresolve/edit)

**值得借鉴**：需要精修时，就地展开所选事件的强度包络，而不是让用户离开时间上下文找另一个设置页。

**延后能力**：JIZURA 先提供“快速衰减／平滑脉冲／持续”三类包络；只有基础编辑稳定且出现精修需求后，再做曲线编辑器。

### 4.5 Apple Motion：行为预设与音频驱动，比纯随机更可解释

Motion 的 Behaviors 可以不用手工关键帧创建运动，行为可添加、移除或禁用；Audio 参数行为将音频分析映射到对象参数，并提供分析方式、延迟、缩放等控制。[来源：Apple 行为概述](https://support.apple.com/en-ie/guide/motion/motn13748883/mac)、[添加、移除与禁用行为](https://support.apple.com/en-ca/guide/motion/motn137463bf/mac)、[Audio 参数行为](https://support.apple.com/en-ng/guide/motion/motn1872e265/mac)

**值得借鉴**：自动生成应有可理解的触发条件。例如“重拍轻震”“句首短闪”“副歌脉冲”，用户能知道为什么在这里出现，也能单独覆盖结果。

**注意区分**：拍点触发离散事件与音频振幅连续驱动参数是两种不同机制。JIZURA 第一阶段可利用已有拍点；不要把已有拍点吸附包装成完整音频响应系统。

### 4.6 对标选择表

| 用户任务 | 主要参考 | JIZURA 应采用的最小机制 | 优先级 |
|---|---|---|---|
| 不懂名称也能选效果 | Final Cut Pro | 分类、搜索、预览卡 | P1 |
| 将效果精确放到歌词／重拍 | CapCut、Resolve | 动效轨、移动、区间、拍点 | P0 |
| 只修改当前事件 | Premiere | 所选对象属性面板 | P0 |
| 自动生成后保留人工控制 | Motion，结合本项目需要 | 来源标识、局部覆盖、锁定 | P0 |
| 对比有没有改善 | Motion 的禁用机制＋本项目同步对比 | 临时旁路、可选双画面 | P1 |
| 重复使用满意的节奏 | Premiere | 复制、预设、锚定规则 | P2 |
| 按音乐形成变化 | Motion | 可解释触发规则、强弱与密度 | P2 |

其中局部覆盖、默认布局和优先级是本报告的设计建议，并非声称这些产品拥有完全相同的机制。

## 5. 建议的信息架构与布局

### 5.1 三种对象分清楚

| 对象 | 回答的问题 | 放置位置 |
|---|---|---|
| 镜头与文字运动 | 字怎么进入、停留、离开；镜头怎么运动 | 镜头编辑 |
| 时间点动效事件 | 在什么时候，持续多久，产生什么全画面变化 | 画面动效工作区 |
| 全片风格与自动规则 | 整体质感是什么；自动选择什么、出现多少 | 可折叠的全片设置 |

“画面动效”入口不再附带“对比”二字。工作区切换、预览显示方式、自动生成状态是三个独立维度。

### 5.3 预览与对比

- 默认显示最终结果。按住“旁路事件”临时预览无时间点事件版本；松开恢复。
- 对比菜单先提供“单画面／并排”；擦拭对比放到后续。
- 标题明确写“原画面（不含时间点动效）／最终画面”，避免误以为原画面没有镜头、转场和基础质感。
- 支持“循环所选”，含可调整前后缓冲；试看应使用播放范围控制，随暂停、切换选择而取消，不依赖失去上下文的定时器。
- 有些效果在起始帧尚不明显。选择事件时定位到其有效预览位置，或保留播放头并提供明显的“预览所选”；由效果元数据定义代表性位置。

## 6. 三条必须顺畅的操作流程

### 流程 A：给一个重拍加轻震

1. 播放头停在重拍附近；吸附开关状态可见。
2. 在效果库预览“轻震”，点击添加或拖入动效轨。
3. 轨道出现事件片段并自动选中，属性面板显示强度和时长。
4. 循环所选，调强度或拖动边缘；按帧微移。
5. 松开操作完成一次撤销记录，其他镜头和事件不变。

### 流程 B：自动生成后只改一个效果

1. 自动结果全部显示在轨道，标注自动来源。
2. 点击事件仅选择，不改项目数据与自动模式。
3. 第一次修改参数时，为该事件建立覆盖，显示“已修改”；支持恢复自动值。
4. 再次生成时，锁定或人工覆盖的部分保留；未锁定的部分按明确范围更新。
5. “全片转为手动”保留为独立操作，明确范围并支持一步撤销。

### 流程 C：保留排版，只给副歌增强动效

1. 选择副歌时间范围。
2. 选择“重拍强调”规则，设置轻／中／强与疏／中／密。
3. 先预览候选事件位置；明确只改所选范围内的动效。
4. 应用后保留歌词、字体、配色和镜头构成；能撤销整个操作。

流程 C 是后续提案，需要增加范围生成能力；当前“全片重新规划”不能被直接视为已经满足该需求。

## 7. 视觉效果本身的设计建议

本节为创作与产品设计提案，未对当前输出画面作实机审美评分。

### 7.1 按表达意图组织，而不是只列技术名

| 面向用户的分类 | 示例方向 | 核心可调项 |
|---|---|---|
| 重拍强调 | 轻震、短闪、缩放脉冲 | 强度、持续拍数、衰减 |
| 数字故障 | 切片、色散、块状故障 | 位移、密度、持续时间 |
| 光感氛围 | 柔光脉冲、柔和闪亮 | 混合量、亮度、范围 |
| 情绪扰动 | 轻微不稳定、间歇扰动 | 幅度、节奏、随机种子 |

其中部分方向可能需要新实现；先盘点现有效果的真实表现和元数据，再决定哪些做成独立效果、哪些只是参数预设。

### 7.2 用时间包络改善质感

同样的“震动＋0.3 秒”，如果从头到尾等幅与快速衰减，观感差异很大。每个预设应包含起始、峰值、衰减，而不仅是类型和倍数。

- 重拍：迅速到峰值、较快回落。
- 氛围：平滑进入、平滑退出。
- 故障：可控的间歇变化，固定种子下可复现。

先提供可理解的三种包络，再考虑开放逐帧曲线。候选值应通过相同歌词、音乐片段和画幅对照筛选，不能仅凭参数数量判断质量。

### 7.3 自动编排需要留白

建议把“每拍都加效果”替换为有规则的稀疏强调：主歌弱、副歌强、句首与关键歌词优先；为高强度效果设置间隔与叠加强度上限。具体密度和阈值需要样片评审确定。

效果库默认展示少量经过筛选的预设，参数允许强度降到 0，并提供禁用与重置。文字可读性应是评审维度之一。

## 8. 实施顺序与技术落点

| 阶段 | 交付范围 | 依赖与注意事项 | 完成标准 |
|---|---|---|---|
| 第一阶段 P0：编辑可控 | 动效轨；选择／移动／时长；局部修改自动事件；撤销一致性 | 不能只把旧 `evHit` 恢复，旧分支仍有自动转手动逻辑；须先明确事件身份与覆盖关系 | 完成流程 A、B，单事件编辑不改变其余事件 |
| 第二阶段 P1：选择与判断 | 效果预览卡；单画面默认；旁路与可选并排；循环所选；分离全片设置 | 优先复用已有预览缓存与可见卡片播放机制；核验双渲染与降质策略 | 不懂技术名也能选择效果；能在有效区间反复比较 |
| 第三阶段 P2：音乐与效率 | 范围生成、复制、收藏／预设、拍数时长、锁定、包络 | 明确绝对时间与歌词／拍点锚定；防止重排后重复或漂移 | 完成流程 C；生成结果可解释、可恢复 |

建议的内部能力补齐：

1. 自动事件增加稳定来源身份：由镜头／触发规则／序号等构成，不在每次规划时任意变化。现有手动 ID 保留。
2. 区分生成结果、人工覆盖、禁用记录和 UI 选择状态。点击不写项目；禁用自动事件应能跨重新规划保留。
3. 为效果定义默认时长、范围、单位、代表性预览位置与支持的包络。切换类型时说明哪些参数保留，哪些恢复默认。
4. 一次拖动或连续参数手势对应一次撤销；键盘编辑同样覆盖。全片固化与清空保持明确的单步事务。
5. 增加“跟随歌词／拍点／绝对时间”的锚定语义，避免生成和手动排时互相覆盖。
6. 拆分项目渲染结果与预览显示方式；旁路、循环和对比不得写入导出配置。

这是对当前模型的增量扩展建议，需要先验证锁定镜头、旧项目载入、自动规划和 AE 导出间的兼容关系，不建议直接替换所有数据结构。

## 9. 验收与后续研究

以下是**待执行的验收标准与研究目标**，不是本次已测得的结果。

### 9.1 功能验收

- 点击任意自动事件前后，项目事件、生成模式和其余事件保持不变。
- 修改一个事件后，其余事件的时间、类型、强度、时长保持不变；重新规划不重复生成被覆盖的事件。
- 拖动和调时长支持鼠标、键盘；按帧微移在 24/30/60fps 下正确；拍点吸附能关闭并有反馈。
- 暂停、切换事件、退出工作区后，不残留上一事件的试看定时行为或循环范围。
- 全片转手动、清空、范围生成和一次参数手势各能一步撤销并恢复。
- 对比两侧时刻一致；旁路只影响预览；保存重开和导出保持最终效果。
- 同时存在多个同类型重叠事件时，能独立选中、删除和修改。
- 旧项目可加载；没有音乐时能自由添加；空事件、事件在片尾、竖屏、窄屏与触屏都有可达操作入口。

### 9.2 小规模可用性研究

建议招募 5–8 位探索性测试参与者，覆盖首次接触的文字 PV 创作者和有剪辑经验者。这是发现问题的试验，不据此推断全体用户的统计结论。

统一任务：添加轻震并对准重拍；仅改一个自动事件；复制一个满意效果；判断调节前后差异；撤销并恢复。

记录首次完成率、耗时、错误次数、求助次数，以及用户能否准确说出当前操作作用于哪里。第一轮目标可设为“至少 80% 参与者无需指导完成添加和调时”；小样本下同时报告人数，避免百分比误导。尚无当前基线，不能宣称已提升多少。

### 9.3 样片与性能验证

- 用同一段素材比较原版与候选方案，覆盖抒情、快节奏、密集歌词及横竖画幅。评审节奏契合、文字可读性、重复感和整体一致性。
- 在约定测试设备与浏览器上测参数到预览的延迟、拖动响应、单／双预览掉帧及效果卡资源占用。目标值在建立基线后确定。
- 对导出做代表性帧与时序抽查，避免仅在低质量预览下判断效果。

## 10. 决策建议

下一轮设计评审应围绕三个可演示结果：**动效轨上的直接编辑、没有全局副作用的单事件修改、可在原素材上反复比较的预览。**

这三个闭环通过后，再投入效果美术筛选、音乐规则和预设扩充。它们分别解决“能不能改”“改了哪里”“好不好看”的问题，优先顺序不宜倒置。
